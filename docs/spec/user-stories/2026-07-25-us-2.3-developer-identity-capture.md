# US-2.3 — Developer Identity Capture

**Slice**: 3 — Core Pipeline
**Status**: Ready for planning

## User Story

As a developer, running `ripe init` tells me my git identity (email, display name) will be
collected and attached to skill invocation events — so I know what's tracked before it happens,
without having to reconfirm on every sync.

## Context

Developer identity as `git config user.email` was decided in
[ADR-002](../../architecture/decisions/ADR-002-developer-identity-source.md). This story adds a
display name alongside it and owns the one-time-per-run consent notice, previously drafted inline
in [US-1.3](2026-07-25-us-1.3-remote-derived-project-identity.md) — pulled out and moved to
Slice 3, alongside skill/event tracking, since it's
about identity capture, not project identity. [US-2.2](2026-06-21-us-2.2-event-submission.md)
consumes `user_email`/`user_name` as event fields; the capture and consent logic live here.

No identity is stored server-side beyond what's already submitted per-event — this story doesn't
introduce a users table or persistent consent flag. Nothing new is cached locally either.

## Scope

**In scope:**

- `ripe init` prints a consent notice to stderr, every run, informing that `git config user.email`
  and `git config user.name` will be collected and submitted with skill invocation events
- No stored consent flag, no per-developer confirmation gate — notice-only
- `ripe sync` reads `git config user.email` and `git config user.name` live at submission time
  (not cached — local git config can change between syncs)
- Missing `user.email` or `user.name` → stderr warning, event submitted with empty string for the
  missing field (consistent with existing `user_email` handling in US-2.2)

**Out of scope:**

- Persistent consent flag or first-run confirmation gate (dropped — see project design-questions
  memory, resolved 2026-07-25)
- Server-side users table / identity persistence beyond per-event fields
- Org-level admin opt-out of identity collection

## CLI Behavior

**`ripe init`:**

1. Prints consent notice to stderr (every run): identity (email, display name) will be collected
   and submitted with telemetry events

**`ripe sync`** (Phase 2, event submission):

1. Reads `git config user.email` → `user_email`; unset → stderr warning, empty string
2. Reads `git config user.name` → `user_name`; unset → stderr warning, empty string

## Acceptance Criteria

- [ ] `ripe init` prints a consent notice to stderr on every run
- [ ] No consent flag is written to `.ripe/cache.json` or anywhere else
- [ ] `ripe sync` reads `user.email`/`user.name` fresh from git config on every run, not cached
- [ ] Missing `user.email` → stderr warning, event submitted with `user_email: ""`
- [ ] Missing `user.name` → stderr warning, event submitted with `user_name: ""`
