# US-2.2 — Event Submission

**Slice**: 3 — Core Pipeline  
**Status**: Ready for planning

## User Story

As the telemetry system, skill invocation events from the just-closed session transcript are
submitted to the server, deduplicated by `(session_id, tool_use_id)`. As a developer, running
`ripe init` tells me my git identity (email, display name) will be collected and attached to
those events, before it happens.

## Context

Event submission is Phase 2 of `ripe sync`, running after skill registration (Phase 1)
has resolved all IDs. It parses the `.jsonl` session transcript, extracts `Skill` tool invocations,
and POSTs them in a single batch (ADR-001).

Deduplication ensures that re-submitting the same transcript (e.g. after a crash) never inflates
counts. Developer identity as `git config user.email` was decided in
[ADR-002](../../architecture/decisions/ADR-002-developer-identity-source.md); this story adds a
display name alongside it (`git config user.name`) and the one-time-per-run consent notice.
Identity is read live at submission time, not cached — local git config can change between syncs.

No identity is stored server-side beyond what's submitted per-event — no users table, no
persistent consent flag.

## Scope

**In scope:**

- `POST /api/events` server endpoint
- Phase 2 of `ripe sync`: parse transcript, resolve IDs, submit batch
- Server-side deduplication on `(session_id, tool_use_id)`
- `ripe init` adds `SessionEnd` hook to `.claude/settings.local.json` if not present
- `ripe init` prints a consent notice to stderr, every run, informing that `git config user.email`
  and `git config user.name` will be collected and submitted with skill invocation events —
  notice-only, no stored flag, no per-developer confirmation gate
- `ripe sync` reads `git config user.email`/`user.name` live at submission time; either missing →
  no event submitted at all (stderr warning, no request made, exit 0)

**Out of scope:**

- Non-Skill tool invocations (ignored)
- Retry logic on network failure (log and exit 0)
- Persistent consent flag or first-run confirmation gate (dropped — see project design-questions
  memory, resolved 2026-07-25)
- Server-side users table / identity persistence beyond per-event fields
- Org-level admin opt-out of identity collection

## API Contract

```text
POST /api/events
Body: Array<{
  skill_id: string      // from local cache (server-assigned)
  skill_name: string    // current name at time of submission
  timestamp: string     // ISO 8601
  user_email: string    // git config user.email, read live, always non-empty
  user_name: string     // git config user.name, read live, always non-empty
  project_id: string    // from local cache
  session_id: string    // Claude Code session ID
  tool_use_id: string   // unique per invocation within the session
  client_type: string   // source adapter, e.g. "claude-code"
}>
→ 204 No Content
```

Server behavior: bulk insert with `ON CONFLICT(session_id, tool_use_id) DO NOTHING`.

## CLI Behavior

**`ripe init`:**

1. Prints consent notice to stderr (every run): identity (email, display name) will be collected
   and submitted with telemetry events

**`ripe sync`** (Phase 2, event submission):

1. Parses the `.jsonl` transcript for `Skill` tool use entries
2. Skips non-Skill tool uses
3. Skips namespaced skills (containing `:`) with a stderr warning
4. Resolves `skill_id` from the local cache (populated in Phase 1)
5. Reads `git config user.email` and `git config user.name`; either unset → stderr warning, no
   request made, exit 0
6. Sets `client_type` to `"claude-code"` on every event
7. Sends all events in one POST
8. If no skill invocations found: exits 0, no request made
9. If server unreachable: stderr warning, exits 0

## Acceptance Criteria

- [ ] All skill invocations in the transcript are submitted in one request
- [ ] Duplicate submissions (same `session_id + tool_use_id`) are ignored by the server
- [ ] No request made if the transcript contains no skill invocations
- [ ] Non-Skill tool uses are ignored
- [ ] Server unreachable → stderr warning, exit 0 (does not block session close)
- [ ] Every submitted event carries `client_type: "claude-code"`
- [ ] `ripe init` prints a consent notice to stderr on every run
- [ ] No consent flag is written to `.ripe/cache.json` or anywhere else
- [ ] `ripe sync` reads `user.email`/`user.name` fresh from git config on every run, not cached
- [ ] Missing `user.email` → stderr warning, no event submitted, exit 0
- [ ] Missing `user.name` → stderr warning, no event submitted, exit 0
